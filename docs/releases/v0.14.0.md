## ClipItTo 0.14.0: 1 bug fix, 3 improvements

**Bug fixes (1)**
- **The name box opens after a copy becomes a password.** With *Ask for a name* on, moving a copy to the Passwords group or choosing
  *Mark as password* now asks for a name, as a password captured from a password manager always did.

**Improvements (3)**
- **Paste as › Number: the bits of a number.** For a number such as `0x123`, the Shift+Enter (and right-click) *Paste as* menu shows
  which bits are set, counting from 0 and highest first (`8 5 1 0`). Text with a `0x` prefix or hex letters is read as hex; digits only
  is read both ways. Numbers over 64 bits are ignored.
- **Paste as › Number: hex, decimal and bits.** The same *Number* submenu pastes the number in the other base (a hex number as decimal,
  a decimal one as hex, an ambiguous one as both) and as bits padded to whole bytes (`2c` becomes `00101100`).
- **Passwords that no password manager marked.** Settings › Passwords has a new checkbox, *Keep copies that look like generated
  passwords as password copies*, **off by default**. A copy from a browser's password field (which sets no marker) that looks like a
  generated password is then kept as a password copy, with the note "Looks like a password". It can wrongly catch ordinary text, which is
  why it is off by default; it needs a master password or *Use without one…*.
