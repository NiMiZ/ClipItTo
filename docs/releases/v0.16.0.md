## ClipItTo 0.16.0: sync through a folder, panic key, paste once, auto-forget, and passwords that lock with the screen

**New (6)**
- **Paste once.** Mark a copy *Paste once* (right-click or Shift+Enter menu, a toggle) and it is removed from the history right after you
  paste it from ClipItTo, and the clipboard is cleared 2 seconds later if it still holds that text (*Settings*: `paste_once_clear_seconds`,
  0 turns it off). It is an item of the **Paste as** menu, so Settings › *Paste as* decides whether it is shown in
  the menu or under *Others*, and where it goes. **Ctrl+Shift+Enter** pastes the selected copy and forgets it in one go. A small *once* tag shows on the row.
  - A password copy is pasted first, then ClipItTo asks *Delete this password copy?* every time; *No* keeps it.
  - Pinned and starred copies are never deleted, only un-marked. Pictures and grouped copies are deleted.
  - If the paste keys were not sent, nothing is deleted. After a deletion, **Undo** (the button, or Ctrl+Shift+Z) restores the copy for 10 seconds.
  - Paste once copies are left out of backups.
- **Auto-forget rules.** Settings › Passwords › *Auto-forget*: up to 8 rules that remove copies by themselves, after N days
  (optionally only text or only pictures), or after N minutes when the text contains a string you give or looks like a token, key or card
  number. Pinned, starred, grouped and password copies are never removed. Rules run at start, once a minute and when the popup opens;
  removals are silent. None are set by default.

- **Sync through a shared folder (off by default).** Settings › *Sync*: pick a folder that Syncthing, Nextcloud, OneDrive or a network share
  already syncs, and set a sync passphrase. Each PC writes one encrypted file there and merges the others' files into its own history
  (text, pictures, and pin, star, group and note state). ClipItTo makes no network connection itself, and the history database is never
  put in the folder. Passwords, copies that look like keys or tokens, and Paste once copies are never synced. `clipitto --sync` runs one
  sync. Set up one PC first and let it write its file before the second one; see [the usage guide](../usage.md) and
  [the design](../sync-design.md).
- **Panic key (off by default).** Settings › Passwords › *Panic key*: one shortcut that wipes the whole history (like *Clear everything, also
  in groups*), locks the passwords and empties the system clipboard, at once and **without asking**. `clipitto --panic` does the same and
  always works, whatever the setting says.
- **The right paste keys for each program.** ClipItTo now picks Ctrl+Shift+V for terminals (Windows Terminal, gnome-terminal, Konsole,
  Alacritty, kitty, WezTerm and others) and Shift+Insert for the Windows console, without changing your global choice. Settings › General
  has the switch and up to 16 rules of your own. It works on Windows, X11 and GNOME Wayland (with the extension: log out and in once after
  updating it); KDE and wlroots Wayland keep the global `paste_keys`.
- **Passwords lock with the screen.** The passwords now lock when the screen locks or the PC goes to sleep (Windows, macOS, and Linux with
  systemd-logind or the GNOME screensaver). On by default; Settings › Passwords has the switch.

**Changed (1)**
- **The clipboard is cleared 2 seconds after pasting a password** (it was 30). *Settings › Passwords*; 0 turns it off, up to 60 seconds. It
  only clears when the clipboard still holds the password, so a newer copy of yours is never wiped.

**Also**
- Copies from KeeWeb are treated as password-manager copies, and a few more macOS clipboard types that mean "temporary" are skipped.
- The database moves to version 11 (new tables for sync and Paste once). Older versions of ClipItTo cannot open a history file that a
  newer one has upgraded.

**Behind the scenes**
- A test-suite of about 340 new automated checks for passwords, grouping, copying from many apps, the GUI, translation and stalls
  (the performance tests found and fixed the stalls listed under 0.15.0).
