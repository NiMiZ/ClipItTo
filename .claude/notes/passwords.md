# Password copies: intended behaviour and what exists

## Intent (user's requirements)
Copies that password managers mark secret are never stored in clear. With a master password they are kept as
sealed copies, hidden in the UI, shown/pasted only after unlock. Without one they are skipped (popup says once
how to enable). Never log clipboard contents. Master password never stored.

## How it works (implemented, v0.6.0)
- **Vault** (`PasswordVault`, Monocypher): master password -> Argon2id (bounds enforced) -> key that encrypts
  an X25519 private key (stored in `vault` row). New passwords are sealed to the *public key* (sealed box:
  X25519 + XChaCha20-Poly1305), so capture works while locked. Unlock decrypts the private key into wiped
  memory; auto-lock after `password_unlock_minutes` (5), `clipitto --lock`, or "Lock passwords".
  Changing the master password re-encrypts only the private key. Forgetting it = passwords lost; "Remove" resets.
- **PasswordKeeper** (daemon-owned): unlock (Argon2id off GUI thread, generation counter drops stale unlocks),
  `reveal(id)`, `markAsPassword`, `unmark`, `search(typed)` (unlocked: substring; locked: exact via keyed hash,
  `findSecrets`), match key = random key in system keyring entry `password-match-key`
  (no keyring => no dedupe, no locked exact search; `--status` says so).
- **Capture**: backends now read marked text and pass source app as pseudo-MIME `x-clipitto-source:<App>`.
  `ClipFilter` checks OwnWrite before Sensitive; Sensitive+vault -> secret path in `CapturePipeline`
  (seal + keyed hash, plain text dropped at once; marked pictures still skipped). Note defaults to source app
  (Windows, X11, GNOME ext; not wl-paste -> "Password"). Windows: ExcludeClipboardContent/CanInclude...;
  mac: ConcealedType kept, TransientType/AutoGeneratedType never recorded.
- **DB**: row has `secret=1`, `content='Password'`; sealed blob in `clip_secrets`; FTS sees label/note/group only.
  "Mark as password" wipes the plain text (secure_delete + WAL checkpoint).
- **Paste**: `ClipboardWriter` adds password-manager markers (so other managers/Windows history skip it);
  cleared from the clipboard after `password_clear_seconds` (30) unless something else was copied.
- **UI**: lock icon + note + ●●●●; Enter / Show password (10 s reveal) asks the master password; Windows Hello
  can unlock (wrapped private-key copy `vault.hello_wrapped`; Linux/mac: disabled with reason). `p[] ` search.
- **Settings** (Passwords tab): keep_passwords, passwords_in_group (files into "Passwords" group),
  show-in-Recent rule for that group, passwords_per_note (needs a master password), password_ask_note
  (name box after a *new* password), unlock minutes, clear seconds, windows_hello, search keyword.
- **Backup**: password copies exported boxed with a key from the master password (see settings-groups-backend.md).

## Limits to remember
Protects the file at rest and other people at your session while locked; not programs running as the user
(they can read the clipboard) and on GNOME the password crosses D-Bus from the extension to the daemon.
No auto-lock on screen lock yet. GNOME extension can put only one format on the clipboard (no markers there).
Not yet hands-on verified: Windows Hello prompt, real KeePass/Bitwarden source-app names, macOS Keychain.
Code: `src/core/{PasswordVault,PasswordKeeper,CapturePipeline,ClipFilter}.cpp`, `src/daemon/WindowsHello_*.cpp`.
Tests: `tst_vault`, `tst_repository`, `tst_pipeline`/popup/search tests, `tst_backup`.
